# Deploying Financial Tracker to Render

This project is set up for Render with Docker and a Blueprint file at `render.yaml`.

The app now includes the backend entrypoint, Sequelize models, protected API routes, and the frontend pages/components needed for the main account connection, transaction grouping, and statement summary flows.

## What Will Be Created

The `render.yaml` blueprint creates:

- `financial-tracker-db`: PostgreSQL database
- `financial-tracker-backend`: Docker web service from `backend/Dockerfile`
- `financial-tracker-frontend`: Docker web service from `frontend/Dockerfile`

The database URL and JWT secret are handled by Render. Plaid keys and the final frontend/backend URLs are entered in the Render dashboard.

## Files Added Or Updated For Render

- `render.yaml`: Render Blueprint for the database, backend, and frontend
- `backend/Dockerfile`: Production Docker image for the Express API
- `frontend/Dockerfile`: Production Docker image for the Next.js app
- `backend/.env.example`: Local backend env template
- `frontend/.env.example`: Local frontend env template
- `.gitignore`: Prevents local env files and build output from being committed

Do not commit real `.env`, `.env.production`, or secret values.

## Environment Variables

### Backend Service

Set these on `financial-tracker-backend` in Render:

| Variable | Value | Where To Get It |
| --- | --- | --- |
| `NODE_ENV`| `production` | Already set in `render.yaml` |
| `PORT` | `5000` | Already set in `render.yaml` |
| `DATABASE_URL` | Render PostgreSQL connection string | Auto-wired from `financial-tracker-db` by `render.yaml` |
| `PLAID_CLIENT_ID` | Your Plaid client ID | Plaid Dashboard -> Developers -> API Keys |
| `PLAID_SECRET` | Your Plaid sandbox/development/production secret | Plaid Dashboard -> Developers -> API Keys |
| `PLAID_ENV` | `sandbox`, `development`, or `production` | Match the Plaid secret you use |
| `JWT_SECRET` | Long random secret | Auto-generated by Render in `render.yaml` |
| `FRONTEND_URL` | `https://financial-tracker-frontend.onrender.com` or your actual frontend URL | Render frontend service -> service URL |

Start with `PLAID_ENV=sandbox` unless you already have Plaid production access approved.

### Frontend Service

Set these on `financial-tracker-frontend` in Render:

| Variable | Value | Where To Get It |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | `https://financial-tracker-backend.onrender.com/api` or your actual backend URL plus `/api` | Render backend service -> service URL |
| `NEXT_PUBLIC_PLAID_CLIENT_ID` | Your Plaid client ID | Plaid Dashboard -> Developers -> API Keys |

Because `NEXT_PUBLIC_*` variables are baked into the Next.js build, redeploy the frontend after changing them.

## Get The Required Values

### Plaid

1. Go to the Plaid Dashboard.
2. Open **Developers** -> **API Keys**.
3. Copy `client_id`.
4. Copy the secret for the environment you want:
   - Sandbox: easiest for initial testing
   - Development: real institutions with limited access, if enabled
   - Production: requires Plaid approval
5. Use the matching `PLAID_ENV` value in Render.

For OAuth institutions or production Link flows, add your deployed frontend redirect URL in Plaid's allowed redirect URI settings. In this app the redirect URI is built from `FRONTEND_URL`.

### Render Service URLs

After each Render service is created, open that service in the dashboard. The public URL appears near the top of the service page.

Use:

- Backend URL in frontend env: `NEXT_PUBLIC_API_URL=https://<backend-service>.onrender.com/api`
- Frontend URL in backend env: `FRONTEND_URL=https://<frontend-service>.onrender.com`

### JWT Secret

The blueprint uses `generateValue: true`, so Render can generate this for you. If you create services manually, generate a long random string locally and paste it into Render.

PowerShell example:

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

## Deploy With Render Blueprint

1. Push this repository to GitHub or GitLab.
2. Open the Render dashboard.
3. Click **New**.
4. Choose **Blueprint**.
5. Connect the repository.
6. Select the branch you want to deploy, usually `main`.
7. Render will detect `render.yaml`.
8. Fill in the `sync: false` values when prompted:
   - Backend `PLAID_CLIENT_ID`
   - Backend `PLAID_SECRET`
   - Backend `FRONTEND_URL` can be temporary at first, for example `https://financial-tracker-frontend.onrender.com`
   - Frontend `NEXT_PUBLIC_API_URL` can be temporary at first, for example `https://financial-tracker-backend.onrender.com/api`
   - Frontend `NEXT_PUBLIC_PLAID_CLIENT_ID`
9. Click **Apply** or **Create Blueprint**.
10. Wait for the database, backend, and frontend services to build.

After the first deployment, confirm the actual Render service URLs and update:

- Backend service: `FRONTEND_URL`
- Frontend service: `NEXT_PUBLIC_API_URL`

Then redeploy both services. Redeploy the frontend last so it bakes in the final API URL.

## Manual Render Dashboard Walkthrough

Use this if you do not want to use the Blueprint.

### 1. Create PostgreSQL

1. Render dashboard -> **New** -> **PostgreSQL**.
2. Name it `financial-tracker-db`.
3. Choose your region and plan.
4. Click **Create Database**.
5. Copy the internal connection string. Use the external connection string only for tools outside Render.

### 2. Create Backend Web Service

1. Render dashboard -> **New** -> **Web Service**.
2. Connect the repository.
3. Select the branch.
4. Set **Name** to `financial-tracker-backend`.
5. Set **Environment** to `Docker`.
6. Set **Root Directory** to `backend`.
7. Leave build/start commands empty so Render uses `backend/Dockerfile`.
8. Add backend environment variables from the table above.
9. For `DATABASE_URL`, use the PostgreSQL internal connection string.
10. Click **Create Web Service**.

### 3. Create Frontend Web Service

1. Render dashboard -> **New** -> **Web Service**.
2. Connect the same repository.
3. Select the branch.
4. Set **Name** to `financial-tracker-frontend`.
5. Set **Environment** to `Docker`.
6. Set **Root Directory** to `frontend`.
7. Leave build/start commands empty so Render uses `frontend/Dockerfile`.
8. Add frontend environment variables from the table above.
9. Click **Create Web Service**.

### 4. Final URL Pass

1. Open the frontend service and copy its public URL.
2. Open the backend service -> **Environment**.
3. Set `FRONTEND_URL` to the frontend URL without a trailing slash.
4. Open the backend service and copy its public URL.
5. Open the frontend service -> **Environment**.
6. Set `NEXT_PUBLIC_API_URL` to the backend URL plus `/api`.
7. Redeploy backend, then redeploy frontend.

## Local Sanity Checks

Run these before pushing:

```bash
docker build -t financial-tracker-backend ./backend
docker build -t financial-tracker-frontend ./frontend
docker compose up
```

Then test:

- Frontend: `http://localhost:3000`
- Backend health route, if implemented: `http://localhost:5000/health`

## Common Render Issues

- **Backend exits immediately**: confirm `backend/src/index.js` exists, `DATABASE_URL` is valid, and `npm start` works locally.
- **Frontend build fails with module not found**: confirm all imported files under `frontend/app`, `frontend/components`, and `frontend/lib` are committed.
- **Database connection fails**: use Render's internal PostgreSQL connection string for services running on Render.
- **CORS error**: `FRONTEND_URL` must exactly match the deployed frontend origin, including `https://` and no trailing slash.
- **Frontend calls localhost**: set `NEXT_PUBLIC_API_URL` in Render and redeploy the frontend.
- **Plaid link-token errors**: confirm `PLAID_CLIENT_ID`, `PLAID_SECRET`, and `PLAID_ENV` all belong to the same Plaid environment.
- **Production Plaid fails**: confirm your Plaid app has production access and your redirect URI/domain is configured in Plaid.
